# 環境差異・セキュリティ・設定分離ルール

## 1. Secrets / トークン・認証情報のコミット厳禁
- **禁止事項**:
  - キーストアの Base64 文字列、Google Play サービスアカウント JSON、GitHub トークンなどの機密情報をリポジトリ内のコード、テスト、ドキュメントに直書きしてコミットすることを固く禁止します。
- **対処法**:
  - テストではダミー値や `unittest.mock` を徹底活用する。
  - GitHub Actions の実行環境では常に `${{ secrets.XXX }}` または `${{ github.token }}` 経由で受け取る。

## 2. クロスプラットフォーム互換性
- **シェルスクリプト**:
  - Composite Action 内の `run` では `shell: bash` を明示し、POSIX 準拠で Linux / macOS / Windows(Git Bash) のいずれでも動作するように記述する。
  - パス区切りには `/` を使用し、変数展開時にはクォート（`"$VAR"`）を徹底する。
- **Windows / 文字エンコーディング**:
  - Python スクリプトはコンソール出力時に Windows（cp932）環境でエンコーディングエラーを起こさないよう、装飾プレフィックスはテキスト（`[INFO]`, `[SUCCESS]`, `[GUARD]` など）を優先し、UTF-8 再設定（`reconfigure`）を考慮する。

## 3. コミット前の差分確認
- コミット前に必ず `git status` および `git diff` を確認し、意図しない一時ファイルやキャッシュ（`__pycache__`, `.pytest_cache`, テンポラリファイル等）が含まれていないことを確認する。

## 4. 一時作業領域 (`scratch/`) の利用徹底
- **一時ファイルの配置場所**:
  - PR 作成用の本文ファイル（`scratch/pr_body.md`）、API 送信用の一時 JSON ファイル、検証用のワンオフスクリプト・ログなどは、**必ず `scratch/` ディレクトリ配下に作成・配置**すること。
  - ルートディレクトリや action ディレクトリ直下に一時ファイルを作成してはならない。
- **Git 除外の保証**:
  - `scratch/` は `.gitignore` に登録されており、誤コミットを未然に防止する。作業完了後は適宜クリーンアップする。
