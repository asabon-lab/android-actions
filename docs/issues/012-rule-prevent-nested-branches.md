# Issue #012: 作業ブランチの数珠つなぎ禁止とブランチ派生ルールの明文化

- **ステータス**: 完了
- **作成日**: 2026-10-08
- **対象ブランチ**: `docs/012-rule-prevent-nested-branches`

---

## 🎯 目的 / 概要

案件を並行・連続して実装する際に未マージの作業ブランチからさらに子ブランチを派生させると、Squash and merge 後のリベース多発、コンフリクト、未マージ PR の累積といった運用上の混乱を招く。
これを防止するため、新規ブランチは原則 `main` から派生させること、およびカレントブランチが `main` 以外の場合は必ずユーザーに方針（マージ待ち / 同一ブランチへの追加 / main からの独立派生）を確認するルールを `AGENTS.md` および `.agents/skills/create-issue/` に明文化する。

---

## 📋 要件 / 受け入れ基準 (Acceptance Criteria)

- [x] `AGENTS.md` の「3. Git / GitHub ワークフロー & コミット規約」に以下のルールが明文化されていること:
  - 作業ブランチから別の作業ブランチを派生させる行為（数珠つなぎ）の原則禁止
  - カレントブランチが `main` の場合: `git pull origin main` 後の新規ブランチ作成
  - カレントブランチが `main` 以外の場合: ユーザーへの方針確認（A: 既存 PR マージ待ち、B: カレントブランチへのコミット追加、C: `main` からの独立派生）の義務化
- [x] `AGENTS.md` の「4. Issue 駆動ワークフロー」のステップ 2（トピックブランチ作成）に上記ルールを反映すること
- [x] `.agents/skills/create-issue/SKILL.md` の手順にブランチ確認およびユーザー確認ステップを追記すること

---

## 🛠️ 設計方針・技術的メモ

- AI エージェントおよび開発者が自律的に判断してブランチを多重派生させることを防ぎ、必ずユーザーの意思決定を挟むことで PR のスタックを未然に防止する。
